# Отчёт по практической работе DevSecOps

**Тема проекта:** IdeaForge — генератор учебных проектов с ИИ  
**Технология:** Java 21, Docker

## Цель работы
Создать API-приложение, связанное с проектной темой, упаковать его в Docker-контейнер и проверить доступность API, состояние контейнера и его логи.

## Реализация
Создано Java API на встроенном HTTP-сервере. Реализованы три endpoint:
- `GET /` — краткая информация о сервисе;
- `GET /health` — проверка доступности приложения;
- `GET /projects/idea` — пример учебной идеи для сервиса IdeaForge.

Endpoint `/projects/idea` связан с темой проекта, потому что возвращает идею учебного проекта, цель и последовательность действий.

## Dockerfile
- `FROM eclipse-temurin:21-jdk-alpine` — выбирает базовый образ с Java.
- `WORKDIR /app` — устанавливает рабочую папку.
- `COPY src ./src` — копирует исходный код в контейнер.
- `RUN javac ...` — компилирует исходный код.
- `EXPOSE 8080` — указывает порт, который использует приложение.
- `CMD [...]` — запускает API при старте контейнера.

## Команды проверки
```bash
docker build -t ideaforge-api:1.0 .
docker run -d --name ideaforge-api -p 8080:8080 ideaforge-api:1.0
docker ps
curl http://localhost:8080/health
curl http://localhost:8080/projects/idea
docker logs ideaforge-api
```

## Ожидаемый результат
`docker ps` показывает контейнер `ideaforge-api` со статусом `Up`. Запрос к `/health` возвращает JSON со статусом `ok`. Запрос к `/projects/idea` возвращает данные об учебном проекте. `docker logs ideaforge-api` показывает сообщение о запуске API и используемом порте.

**Важно:** скриншоты и реальный вывод команд необходимо сделать после запуска Docker на своём компьютере.
